# 戦略書: 日程調整ツール競争戦略

## 1. アイデンティティ

> **調整さんと同じ登録不要・URL共有の手軽さで、結果をCSV・ICSで持ち出せるモダンUIの日程調整ツール**

### なぜこのツールを使うのか（3つの理由）

1. **結果を持ち出せる**: CSV（Excel対応）とICS（カレンダー連携）で日程調整の結果を自分のツールに取り込める。調整さんにはない機能
2. **作成後に編集できる**: 候補日の追加・削除、イベント情報の修正が可能。調整さんでは作り直しが必要
3. **モダンで使いやすい**: ダークモード対応・レスポンシブ・アニメーション付きの現代的なUI。コピーURL共有・PWA対応

## 2. 競合ポジショニング

> 詳細な10社分析は [09_competitive_analysis.md](./09_competitive_analysis.md) を参照

### 脅威度別の競合整理

**脅威度: 高**

| 競合 | 強み | 弱み | 本ツールとの差別化 |
|------|------|------|-------------------|
| **調整さん** | 圧倒的認知度、極限のシンプルさ、先行者優位 | UI古い、作成後編集不可、エクスポート不可 | CSV/ICS出力、編集機能、モダンUI |
| **LINEスケジュール** | LINE内で完結、LINEグループの配信力で回答率極めて高い、9700万MAU基盤 | LINE外で使えない、時間帯指定不可、エクスポート不可、PC体験が貧弱 | ブラウザベース、プラットフォーム非依存、時間帯指定可、結果出力 |

**脅威度: 中**

| 競合 | 強み | 弱み | 本ツールとの差別化 |
|------|------|------|-------------------|
| **トントン/伝助** | 登録不要・URL共有で同じ土俵、SEO上位 | UIが2010年代、エクスポート不可 | モダンUI、CSV/ICS出力 |
| **Googleカレンダー候補日時** | Google基盤に統合、追加ツール不要 | 投票型調整ができない、双方にGoogleアカウント必要 | 登録不要、グループ投票型、プラットフォーム非依存 |

**脅威度: 低**（ターゲット/言語/モデルの不一致）

| 競合 | 不一致の理由 |
|------|------------|
| **Spir** | ビジネス1対1×カレンダー連携。登録必須・有料 |
| **TimeTree** | 共有カレンダーアプリ。単発調整のユースケースと異なる |
| **Doodle** | 日本語対応弱い、有料誘導がUXを損ねる |
| **When2meet / LettuceMeet** | 英語のみ。日本市場では無名 |
| **Calendly** | 予約型(1対1)。登録必須・高額・日本語未対応 |
| **MS Bookings/FindTime** | Microsoft 365前提。B2C市場で存在感なし |

**攻めるポジション**: 登録不要 × 日本語ネイティブ × モダン × 結果活用（CSV/ICS）

### LINEスケジュールへの対抗戦略

LINEスケジュールは初期ターゲット（大学生）と最も重なる最大の脅威。
URL共有型はLINEグループ内配信の回答率に構造的に劣る。

**対策**:
- 初期ターゲットを「大学生」から「副業/フリーランスの対外調整」「勉強会/イベント主催者」に修正
- これらのセグメントではLINEグループで調整しない（社外クライアント、不特定参加者）
- CSV/ICSエクスポートはこのセグメントにこそ価値がある（結果を別システムで管理する需要）

## 3. キラーフィーチャー（2つ）

### #1 結果活用 = 乗り換え動機

- **CSV出力（既存強化）**: UTF-8 BOM付きでExcel互換。集計行付き。数式インジェクション対策済み
- **ICSエクスポート（新規）**: 確定日程をGoogleカレンダー/Outlook/Apple Calendarにワンクリック追加
- **おすすめバッジ**: 最高スコアの候補日に「おすすめ」ラベルを自動表示

### #2 作成後の編集 = 定着動機

- **候補日の追加/削除**: 作成後でも候補日を変更可能
- **イベント情報の修正**: 名前・説明・期限の修正
- **日程確定**: 主催者がワンクリックで日程を確定

### 獲得→定着の2段構え

```
回答者がURL経由で初回利用 → 回答完了CTAで作成を促す → CSV/ICS出力で「便利」体験
→ テンプレート的に再利用 → 編集機能で定着 → 次のイベントも本ツールで作成
```

## 4. ターゲットユーザー

### 初期ターゲット（Phase 1）-- 競合分析に基づき修正

| セグメント | ペルソナ | 利用シーン | なぜこのセグメントか |
|-----------|---------|-----------|-------------------|
| **副業/フリーランス** | 30代、効率重視 | クライアントとのMTG調整 | LINEグループで調整しない（対外調整）。ICSで確定日程をカレンダー反映したい需要あり |
| **勉強会/イベント主催者** | 20-40代、IT系 | 勉強会・もくもく会・LT会 | 不特定参加者への公開URL共有。CSV出力で出欠管理したい需要あり |
| **小規模チーム** | 5-20人、IT系 | 週次MTG、プロジェクト | 社外メンバー含む調整（LINEグループに入れない人がいる） |

**除外セグメント**: 大学生/サークルはLINEスケジュールとの直接競合を避けるため、初期ターゲットから外す。認知拡大後の自然流入は妨げない。

### Phase 1の目標

- **個人ユーザー100人獲得**（月間アクティブイベント作成者）
- 主要な獲得チャネル: プロダクト内バイラル（回答完了CTA + Powered byリンク）

## 5. 成長戦略

### Phase 1b: プロダクト内バイラル

1. **回答完了CTA**: 回答送信後にモーダルで「あなたもイベントを作成しませんか?」
2. **Powered byリンク**: フッターに「Powered by 日程調整ツール」リンク
3. **UTMパラメータ追跡**: `?ref=response_cta` / `?ref=powered_by` で効果測定
4. **共有URLにUTM**: `?utm_source=share&utm_medium=link` で外部共有の流入測定

### Phase 2以降（検討段階）

- SEO最適化（Next.js SSR/SSG活用）
- 技術記事によるオーガニック流入（Qiita/Zenn）
- SNS共有ボタン

## 6. マネタイズ方針

### Phase 1: 完全無料（ユーザーベース構築に集中）

マネタイズは実装しない。100人のアクティブユーザー獲得が最優先。

### マネタイズが困難な構造的理由

| 障壁 | 説明 |
|------|------|
| 競合の無料圧力 | 調整さん・LINEスケジュールが完全無料。価格差が即座に乗り換え障壁になる |
| 利用頻度の低さ | 日程調整は月1-2回。月額課金の価値を感じにくい |
| 登録不要とマネタイズの矛盾 | 課金対象のユーザーを識別できない。「登録不要」がコアバリューなのに登録を求めるのはブランド矛盾 |
| 機能差別化の模倣容易性 | CSV/ICSエクスポートは調整さんが1週間で実装可能。持続的な有料化の根拠にならない |

### Phase 2以降: マネタイズ候補の比較評価

| モデル | 有望度 | メリット | デメリット |
|--------|:------:|---------|-----------|
| **Freemium（段階的登録）** | ★★★ | マジックリンク認証（メールのみ）でハードル最小化。「登録不要で基本機能、メール登録でテンプレート・履歴管理」という二層構造 | 無料の調整さんとの価格差。コンバージョン率1%以下のリスク |
| **B2B/チーム課金** | ★★★ | 企業単位の月額課金はLTVが高い。SSO・監査ログ・カスタムブランディングが差別化 | SSO等の開発コスト高。小規模チームではオーバースペック |
| **広告モデル** | ★★ | 回答ページは1イベントにN人がアクセスするためPV効率が良い | UXを損ねる。日程調整ツールへの広告はCPM単価が低い |
| **API課金** | ★★ | Slack Bot等からの日程調整API利用。競合が少ないニッチ | 市場規模が小さい。API利用者は開発者に限定 |
| **ホワイトラベル/OEM** | ★ | 企業が自社ブランドで埋め込み。高単価 | 開発・サポートコスト大。カスタマイズ要求が際限なく膨らむリスク |
| **寄付/スポンサー** | ★ | OSSコミュニティモデル。開発自由度が高い | 持続性に疑問。収益予測不能 |

### 推奨マネタイズパス

```
Phase 1: 完全無料
  │ ユーザー100人獲得
  │ CSV/ICSの実際の利用率を定量検証
  ▼
Phase 2a: Freemium導入（メールアドレスのみのマジックリンク認証）
  │ 無料: 現在の全機能
  │ Pro (月500円): テンプレート保存、マイイベント履歴、Googleカレンダー連携
  │ ※ 有料機能は「効率化」。基本の日程調整は永久無料
  │ ユーザー行動データでB2B需要を確認
  ▼
Phase 2b: B2B検討（需要確認後のみ着手）
  │ Team (月2,000円〜): SSO、チーム管理、カスタムブランディング
  │ ※ SSO実装は需要確定後
  ▼
Phase 3: データに基づく判断
  │ ユーザー数、コンバージョン率、解約率から最適モデルを決定
  │ 広告 or API課金も選択肢として残す
```

### 「登録不要」とマネタイズの両立設計

| レイヤー | 認証 | 利用可能機能 | 費用 |
|---------|------|------------|------|
| 匿名（Layer 1） | なし | イベント作成・回答・CSV/ICS出力・編集（edit_keyベース） | 無料 |
| メール認証（Layer 2） | マジックリンク | + マイイベント履歴、テンプレート、Googleカレンダー連携 | Pro: 月500円 |
| 組織（Layer 3） | SSO/SAML | + チーム管理、監査ログ、カスタムブランディング | Team: 月2,000円〜 |

**重要原則**: Layer 1（匿名）だけで日程調整の全基本機能が使える。課金は「繰り返し利用の効率化」にのみ適用。この原則を破ると「登録不要」のブランドが崩壊する。

### MVP後の検証項目（マネタイズ判断の前提データ）

| 指標 | 目標値 | 測定方法 |
|------|--------|---------|
| CSV出力の利用率 | イベントの10%以上 | APIアクセスログ |
| ICS出力の利用率 | イベントの5%以上 | APIアクセスログ |
| 編集機能の利用率 | イベントの20%以上 | APIアクセスログ |
| リピート作成率 | 月2回以上作成するユーザーが20% | localStorage + UTMトラッキング |
| バイラル係数 | CTA経由の新規作成が全体の10%以上 | `?ref=response_cta` パラメータ |

これらの数値がマネタイズ判断の定量的根拠になる。数値が低い場合はマネタイズよりも機能改善を優先する。

## 7. やらないことリスト

以下は現在のフェーズでは実装しない:

| 項目 | 理由 |
|------|------|
| Googleカレンダー連携 | OAuth審査コスト高、MVP後のキラーアップデートとして温存 |
| テンプレート/繰り返しイベント | ユーザーフィードバック後に優先度判断 |
| WebSocket/リアルタイム更新 | 日程調整は非同期利用が主、過剰設計 |
| AIスコアリング | 登録不要モデルでは行動データ蓄積不可 |
| B2B SSO/SAML | Phase 2以降、かつユーザーベース構築後 |
| モバイルネイティブアプリ | PWAで代替 |
| OGP画像動的生成 | 固定ロゴ画像で代替 |
| ダークモード最適化 | 既存実装を維持するが新規投資はしない |
| Chakra UI v3移行 | Phase 2で計画。現在のv2で動作に問題なし |
| 多言語対応 | 日本市場に集中 |

## 8. リスクと対策

| リスク | 影響度 | 対策 |
|--------|--------|------|
| **LINEスケジュールとの競合**（初期ターゲット） | **最高** | 初期ターゲットを大学生から副業/フリーランス/イベント主催者に変更。LINE外で調整するセグメントに集中 |
| 調整さんのUI刷新 | 高 | 結果活用（CSV/ICS）+ 編集機能で防御可能な差別化を維持 |
| GoogleがCalendar内に投票機能を統合 | 高 | プラットフォーム非依存・登録不要を堅持 |
| CSV/ICSの需要が仮説どおりでない | 高 | MVPリリース後に利用率を定量検証。数値が低ければキラーフィーチャーを「作成後編集」に軸足移動 |
| セキュリティインシデント | 高 | Phase 0で全脆弱性を修正 |
| マネタイズパスが見つからない | 中 | Phase 2まではサーバーコスト最小化（Celery/Redis削除済み）。広告モデルも選択肢に残す |
| React 19 + Chakra UI v2の互換性 | 中 | 動作確認済みの前提。問題発生時はv3移行を前倒し |
| 個人情報保護法対応 | 中 | Phase 0でプライバシーポリシー策定 |
| 「登録不要 × マネタイズ」の矛盾 | 中 | 3層認証（匿名/マジックリンク/SSO）で段階的に解消。Layer 1は永久無料を堅持 |
