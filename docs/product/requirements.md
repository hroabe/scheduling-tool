# 要求仕様（PRD）— 日程調整ツール v2.0

## 1. 背景 / 解決したい課題
- 複数人の空き時間調整を「URL共有だけ」で完結したい
- 回答状況を集計し、最適候補を提示し、確定まで一気通貫にしたい
- 回答期限のリマインドや通知の手間を減らしたい

## 2. ターゲットユーザー
- 小規模チーム/サークル/家族/学校行事の幹事
- 登録やアプリ導入が面倒な相手が混ざるケース

## 3. 価値提案（VP）
- 登録不要、URL共有で回答
- 直感UI（レスポンシブ/ダークモード）
- 自動集計、確定、CSV出力
- メール通知（回答通知/期限リマインダー）、通知ログ

## 4. スコープ
### In scope（現状）
- イベント作成（UUID共有URL）
- 候補日登録（開始/終了）
- ◯△×回答 / 編集（トークン）
- 回答期限 / 確定
- 通知（回答時メール、期限リマインダー、通知ログ）
- CSV出力 / 集計API
- 管理（編集キー認証、古いデータ削除）
- UI（ダーク/レスポンシブ）
- Mobile（RN基本）

### Out of scope（当面）
- 大規模組織向けの承認ワークフロー
- 複雑な会議室/リソース予約（まずは個人カレンダー連携優先）

## 5. 非機能要件
- 可用性: 個人〜小規模利用を想定（障害時の復旧手順を docs 化）
- 性能: 体感高速（集計はNが増えても破綻しない）
- セキュリティ: URL/トークン/編集キーの漏洩対策、PII最小化
- プライバシー: 参加者の個人情報を必要最小限に
- 保守性: 仕様と実装の同期（RFC/Docs必須）
- 運用性: 通知失敗の再試行、ログで追跡可能

## 6. ドメイン用語
- Event/Schedule: 日程調整イベント本体（UUIDで共有）
- Candidate: 候補枠（開始/終了）
- Response: 参加者の回答（◯△×）
- Edit Token: 回答編集用のトークン
- Admin Edit Key: イベント編集/確定の管理キー
- Notification Log: 通知履歴

## 7. 機能要件（要約）
### 7.1 イベント作成
- 幹事はイベントを作成し、共有URL（UUID）を取得できる
- 候補枠を登録できる（開始/終了）

### 7.2 回答
- 参加者は共有URLから回答できる（◯△×）
- 回答編集は Edit Token により可能（リンク再アクセスで編集）
- 期限後の扱いはルールを明確化（既定: 新規回答不可、編集可/不可は設定）

### 7.3 集計/確定
- 集計APIで候補ごとの集計結果を取得できる
- 幹事は確定操作ができる（Admin Edit Key）
- 確定後の通知（メール/将来: カレンダー登録）

### 7.4 通知
- 回答があったら幹事にメール通知
- 期限前にリマインダー
- 通知ログを保存し、再送/監査できる

### 7.5 データ保持
- 古いデータは自動削除（保持期間は設定可能にする余地）

## 8. 受け入れ基準（サンプル）
- 共有URLから、未登録ユーザーでも回答できる
- 回答編集は Edit Token が無いとできない
- 期限リマインダーが一度だけ送られ、ログに残る
- CSV出力が集計結果と整合する

## 9. 追加機能（Backlogの核）
- 高優先: Google/Outlook連携、ユーザー認証、会議URL自動発行、1対1モード
- 中優先: LINE/Slack通知、テンプレ複製、QR、i18n、締切後自動督促、PW/IP制限、WebSocket
