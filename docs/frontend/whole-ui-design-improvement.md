# UI改善仕様書（イベント管理：通常の日程調整） v1.0
対象：Desktop / Mobile 共通（My Events / Event Status / Respond / Summary）

## 0. 目的（Why）
現状のUIは機能実装はできているが、画面ごとに見た目の統一感が弱く、境界（背景・カード）の視認性が不足し“プロっぽさ”が出ていない。
本改善では **「テイストは変えず、軽さを維持したまま“見やすさと統一感”を上げる」**。

## 1. ゴール（What）
- 見た目の統一：余白、角丸、枠線、影、タイポグラフィ、色（背景/カード/文字）を全ページで統一
- 視認性の改善：背景とカードの分離感を **コントラストだけに頼らず**（薄い境界＋影＋余白）で実現
- 主要コンポーネントの再設計：Tabs / Table / Badge / Progress / Cards / Buttons / Forms を統一ルール化
- 日本語の可読性：Noto Sans CJK（JP系）を標準フォントにし、文字化け・字詰め崩れを防止
- UIのみ変更：ロジック/データ構造/機能は変更しない（見た目・レイアウト・アニメ・アクセシビリティ改善はOK）

## 2. 非ゴール（What not）
- 情報設計の大規模変更（画面遷移、機能追加、DB/API変更）
- ブランド刷新（色相・雰囲気を大きく変える）
- コピーの大幅な変更（文言は基本維持。必要なら微調整程度）

## 3. デザイン方針（Principles）
### 3.1 テイスト
- クリーン + ほんのりブルー（現状の印象を維持）
- “軽さ”を出すため背景は淡い青み、カードは白系を基本にする

### 3.2 視認性の作り方（重要）
- 「コントラストを上げる」より **分離感を設計**
  - 背景をほんの少し暗く/彩度を落とす
  - カードは白（または僅かに白Alpha）維持
  - 枠線は薄いまま、影を“薄く広く”足す
  - hover/activeの時だけ枠線を濃くして操作感を出す

## 4. デザイントークン（Chakra theme / semanticTokens）
### 4.1 フォント（必須）
- Font family（優先順）：
  - `"Noto Sans JP", "Noto Sans CJK JP", "Noto Sans CJK", system-ui, -apple-system, "Segoe UI", "Hiragino Kaku Gothic ProN", "Yu Gothic", sans-serif`
- 全ページ共通で適用（Themeで指定）

### 4.2 カラートークン（B案：青みを少し残して見やすく）
> 値は目安。実装時は既存のchakraカラーに寄せてOK（blue.50 / gray.200 等）

- `bg.page`：`blue.50` 相当（例：#F5F8FF 近辺）
- `bg.card`：`white`
- `border.subtle`：`gray.200`
- `border.strong`（hover/active/focus）：`gray.300`〜`gray.400`
- `text.primary`：`gray.800`
- `text.secondary`：`gray.600`
- `text.muted`：`gray.500`
- `shadow.card`：薄い“広い影”＋小さい影（2層推奨）
- `focus.ring`：`blue.300`（透明度を含めてOK）

### 4.3 角丸・余白・線
- Radius：
  - Card：`12px`（= `xl`相当）
  - Button：`10px`
  - Badge：`999px`
- Spacing：
  - セクション間：`24px`
  - カード内：`16px`〜`20px`
  - 行高：本文 `1.6`
- Border：
  - 1px固定、色は基本 `border.subtle`

## 5. 共通レイアウト（App Shell）
- 背景：`bg.page`
- コンテンツ幅：
  - Desktop：最大 `1120px`〜`1200px`、左右余白 `24px`
  - Mobile：左右余白 `16px`
- ページヘッダー（イベント名＋ステータス＋メタ＋アクション）を共通コンポーネント化
- 主要カード（Tabs / Table / Summary / Reminder）を同じcardスタイルで統一

## 6. 画面別UI要件（ページ構造は維持しつつ見た目を統一）
### 6.1 My Events（一覧）
- 検索バー/フィルタ/並び替え：同一高さ、同一余白、同一ボーダー
- イベントカード：
  - タイトル：太字、1行で省略（tooltip任意）
  - メタ：候補数/回答数/作成などはsecondary text
  - 進捗：直線バー（角丸小さめ 4px程度）
  - CTA「開く」：カード内に収め、はみ出しゼロ（minW & flexで保護）
- hover：カードのshadowを1段上げ、borderを`border.strong`へ

### 6.2 Event Status（回答状況）
- Tabs：下記の「Tabs仕様」を適用
- テーブル：下記の「Table仕様」を適用
- 参加者行：
  - Avatar＋名前：左固定、行高整える
  - ○△×：セル中央寄せ、サイズ統一（アイコン/チップの高さ揃え）
  - コメント列：右、編集/削除アイコンはホバー時に表示（常時表示でもOKだが主張を弱める）
- 集計行：
  - “集計”は視覚的に区切る（薄い背景 or divider）
- 未回答リマインドカード：
  - ページ内カードデザインと同じ
  - 重要度は上げるが、色を派手にしすぎない（淡い青枠+アイコン）

### 6.3 Respond（回答フォーム）
- 入力フォーム：Card内に統一
- 候補行（各候補の出欠選択）：
  - 左：日付＋時間（強弱のあるタイポ）
  - 右：○△×の3つボタンは同一幅/同一高さ、押下状態が一目で分かる
  - hover/focus：アクセシブルなfocus ring
- 送信CTA：ページ下で目立たせるが、余白/高さを他ボタンと統一

### 6.4 Summary（集計結果）
- KPIカード（回答者数/最大○数/候補日数）：
  - 3カラム（Mobileは縦積み）
  - アイコン背景は淡いトーン、数字を主役に
- 候補日ごとの回答状況：
  - 左：候補日一覧（バー＋○数のピル）
  - 右：おすすめ候補の大カード（おすすめバッジ + 内訳○△×）
  - 選択で右カードが切り替わるUIはOK（既存ロジック維持）
- “確定”状態（実装済みなら表示を整える）：
  - 確定済みの候補は緑系の「確定」バッジ
  - 未確定なら“確定する”ボタン（danger/primaryの色設計は統一）

## 7. コンポーネント仕様（共通化）
### 7.1 Tabs（改善対象：美しくない）
- コンテナ：カード内タブ（白背景）
- タブ:
  - 高さ：`40px`
  - 余白：左右`14px`
  - Active：背景は薄い青 (`blue.50`程度)、下線はprimary
  - Inactive：文字は`text.secondary`
  - Hover：薄い背景
- 下線を太くしすぎない（2px程度）
- 角丸：グループ全体丸、タブ自体も丸（pillではなく“ソフトな角丸”）

### 7.2 Table（改善対象：プロっぽく）
- 테ーブルは“箱”としてカードに入れる（table自体は透明でOK）
- Header：
  - 背景：`gray.50` + 薄いボーダー
  - sticky（可能なら）※Mobileでは横スクロールの負担を軽減
- Row：
  - zebraは弱め（または無し）、hover時に薄い背景
  - 行間とアイコンサイズを厳密に揃える
- セル内の○△×：
  - “チップ”の高さを統一（例 28px）
  - ○△×の色は現状のトーン維持（パステル系でOK）
- 横幅：
  - Desktop：候補列が多い場合は横スクロール（scrollbarを美しく）
  - Mobile：候補列は横スクロール + 左列（参加者）をsticky推奨

### 7.3 Badge / Chip / IconButton
- Badge：角丸999、背景は淡く、文字は濃くしすぎない
- IconButton：枠線薄、hoverでbg、focus ringあり

### 7.4 Progress bar
- 直線（端は軽く丸める程度 4px）
- 背景トラックは薄いグレー、値はprimaryブルー
- “楕円形に見える”はNG（丸すぎ注意）

## 8. レスポンシブ（必須）
- Breakpoints：
  - Mobile：〜768
  - Desktop：>= 1024
- Mobile:
  - Tabsは横スクロール不可にしない（詰まるなら折返し/スクロール）
  - Tableは横スクロール + sticky列で視認性確保
  - CTAは画面幅に合わせてフル幅化（ただし余白は維持）

## 9. アクセシビリティ / 体験
- フォーカスリング必須（キーボード操作）
- コントラスト：本文は十分（AAAまでは不要だが読みづらさ禁止）
- ホバー/押下/disabledの状態を必ず用意

## 10. 受け入れ条件（Acceptance Criteria）
- 全8画面（Desktop 4 / Mobile 4）で、余白・角丸・枠線・影・タイポが統一されている
- 背景とカードの分離が「線だけ」に依存せず、影+構造で見やすい
- Tabsが“段差・不自然な枠”なく、自然に見える
- Tableの行高・アイコン・余白が揃い、素人っぽさが消える
- Noto Sans CJK系フォントが全画面に適用され、日本語の崩れがない
- “はみ出し”ゼロ（開くボタン等）
- UI変更で機能が壊れていない（E2E/手動確認で主要動線OK）

## 11. 実装方針（How）
- Chakra theme の `semanticTokens` と `components` overrides で土台を作る
- Card / Tabs / Table / Badge / Button / Input の基底スタイルを先に統一
- 各ページは基底コンポーネントの組み合わせで見た目を揃える
- 既存のCSS直書きがある場合は段階的にChakra propsへ寄せる
