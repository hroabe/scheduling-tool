# docs/lp-spec.md
# LP（トップページ）仕様 v1.1（多言語8対応・翻訳はエージェント）
対象: Next.js App Router + Chakra UI 既存プロジェクト
目的: 個人ユースで刺さるLPを完成させ、投票型（複数人）→1on1予約（ビジネス）へ自然に導線を作る

---

## 0. 成功指標（MVP）
- 1) ファーストビューで「投票（複数人）/ 1on1予約」の両方が一瞬で分かる
- 2) 主CTAが迷わず押せる（SPでも押しやすい）
- 3) 既存LP構造を維持しつつ、コピーと導線で改善
- 4) 多言語 8言語対応（翻訳はエージェントが実施）
- 5) 記号表示ルール（○△× / ✓ ? x）が言語ごとに正しく切り替わる

---

## 1. 対応言語
- 対象ロケール: `ja`, `en`, `zh`, `ko`, `es`, `fr`, `de`, `pt`
- 既存の言語セレクタがある場合はそれに統合
- 無い場合は `?lang=` クエリで切替（例 `/?lang=en`）

---

## 2. 記号表記（重要）
### 2.1 Availability Symbols（投票の表記）
- `ja`, `ko`：`○ △ ×`
- それ以外（`en`, `zh`, `es`, `fr`, `de`, `pt`）：`✓ ? x`

### 2.2 実装要件
- 文言中に直書きせず、必ず `availabilitySymbols(lang)` のような関数で取得し表示する
- チップ/機能紹介/手順/FAQ等、投票表記が出る箇所はすべてこの関数経由にする
- 例）「○△×集計」/「✓ ? x poll」など、言語によって差し替え

---

## 3. 情報設計（ページ構造）
LPは1ページで完結し、下記セクション順で構成する。

1. Header（ロゴ/ナビ/言語/CTA）
2. Hero（H1/サブ/チップ/CTA/モック画像）
3. Mode Selector（新設：投票/1on1の2択）
4. Steps（3ステップ）
5. Use Cases（こんな時に便利）
6. Feature Grid（基本機能）
7. FAQ（Accordion）
8. Bottom CTA（強いCTA）
9. Footer

---

## 4. ルーティング/リンク要件
- LP: `/`（または既存トップ）
- 主CTA: 既存の作成画面へ遷移（例 `/new`）
- 「モード」を渡せるようにする:
  - `?mode=group`（投票型）
  - `?mode=1on1`（1on1予約）
  例: `/new?mode=group`
- Secondary CTA（デモ）は既存が無ければ #demo アンカーでOK

---

## 5. コピー（ソースは日本語を正本とし、翻訳はエージェントが作る）
### 5.1 ソース日本語（正本）
※LPに表示する“意味”としては以下を満たす。表現は多少調整してよい。
- Hero:
  - H1: 日程調整を、もっとシンプルに。
  - Sub: 登録不要。候補日を作ってURLを送るだけ。投票（可/微妙/不可）が集まり、最適な日程がすぐ分かります。さらに1on1予約も同じ流れで使えます。
  - Chips: 登録不要 / URL共有 / （投票の記号） / 1on1予約
  - CTA: 無料で作成する / デモを見る
  - Micro: ※主催者も参加者も、ログインなしで使えます（無料）
- Mode Selector:
  - 見出し: 用途に合わせて選べます
  - Card1: みんなで調整（投票）
  - Card2: 1on1予約（空き枠→確定）
- Steps:
  - 見出し: 使い方は3ステップ
  - Step: 作成 → URL共有 → 集計→決定（または予約確定）
  - Note: 最短1分。あとは回答を待つだけ。
- Use Cases（3つ）:
  - チームMTG / 飲み会・イベント / 1on1・面談
- Features（6つ）:
  - URL共有で即回答 / （投票の記号） / リアルタイム集計＆提案 / 期限設定＆リマインダー / 多言語対応 / セキュア設計
- FAQ（4〜6）:
  - 登録は必要？ / 候補変更できる？ / 回答は簡単？ / 締切設定できる？
  - 任意: 1on1予約もログイン不要？

### 5.2 翻訳要件（エージェントが作成する）
- 対象: `en`, `zh`, `ko`, `es`, `fr`, `de`, `pt`
- 方針:
  - 直訳ではなく “LPとして自然で短い” 表現にする（特にHeroとCTA）
  - 誇大広告にしない（例：最短30秒等は根拠が無ければ避けるか「最短1分」へ）
  - `ja/ko`以外の投票記号は必ず `✓ ? x` を使用
- 文字量制約（目安）:
  - H1: 1〜2行（SPで崩れない）
  - Sub: 2〜3行程度
  - Chip: 2〜4語程度
  - CTA: 2〜8文字（英語は短く）

---

## 6. UI/デザイン要件（Chakra）
- 既存LPの青基調・カード・余白を踏襲
- Hero背景（青）は維持、カードは白 + 角丸 + 控えめシャドウ
- チップは折返し制御（2行まで）
- 見出し階層を正しく（h1→h2→h3）

---

## 7. レスポンシブ要件
- Header: SPハンバーガー / PC横並び
- Hero: PC 2カラム（左テキスト/右画像） / SP 縦積み
- Mode Selector: PC 2カラム / SP 縦積み
- Features: PC 3列×2段 / SP 2列or1列
- CTA: SPで押しやすいサイズ（幅100%も可）

---

## 8. 実装要件（コンポーネント分割）
推奨例:
- `app/page.tsx`（既存に合わせる）
- `components/lp/*Section.tsx`
- `lib/i18n.ts`（簡易辞書）
- `lib/availabilitySymbols.ts`（言語→記号）
- `locales/ja.ts`（日本語正本）
- `locales/en.ts`, `zh.ts`, `ko.ts`, `es.ts`, `fr.ts`, `de.ts`, `pt.ts`（エージェント作成）
