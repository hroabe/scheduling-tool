# RFC-0006: 多言語対応（i18n）

## 概要
日程調整ツールを多言語対応し、日本国内の外国人ユーザーや国際チームでの利用を可能にする。

## 背景
- 日本国内の在日外国人（約300万人）、外資系企業、国際チームからのニーズ
- 日本語ネイティブ品質 + 多言語対応の組み合わせは競合の空白地帯
- 実装コストが低く、差別化効果が高い

## 対象言語（優先順）
1. **Phase 1**: 日本語（既存）+ 英語 ✅ 完了
2. **Phase 2**: 中国語（簡体字） ✅ 完了
3. **Phase 3**: 韓国語、スペイン語、フランス語、ドイツ語、ポルトガル語 ✅ 完了

## 設計方針

### Backend (Django)
- Django標準の `django.utils.translation` を使用
- Accept-Language ヘッダーで言語自動検出
- ユーザー設定で言語固定可能（UserProfile.preferred_language）
- メッセージカタログ: `api/locale/{lang}/LC_MESSAGES/django.po`

### Frontend (Next.js)
- `next-intl` または `next-i18next` を使用
- URL構造: `/{lang}/...` （例: `/en/schedule/...`）
- 言語切替UI（フッターまたはヘッダー）
- ブラウザ言語自動検出 + Cookie保存

### Mobile (React Native)
- `i18n-js` + `expo-localization` を使用
- デバイス言語自動検出
- AsyncStorageで言語設定を永続化

### 翻訳対象
1. **UI文字列**: ボタン、ラベル、エラーメッセージ
2. **メール通知**: 件名、本文テンプレート
3. **API エラーメッセージ**: バリデーションエラー等
4. **日付/時刻フォーマット**: ロケール対応

## API変更

### ヘッダー
```
Accept-Language: ja, en;q=0.8
```

### UserProfile拡張
```python
class UserProfile(models.Model):
    preferred_language = models.CharField(
        max_length=10,
        default='ja',
        choices=[('ja', '日本語'), ('en', 'English'), ...]
    )
```

### Schedule拡張（オプション）
```python
class Schedule(models.Model):
    # 公開ページのデフォルト言語
    default_language = models.CharField(max_length=10, default='ja')
```

## 非機能要件
- 翻訳キー追加時にビルドエラー（TypeScript型チェック）
- 未翻訳キーはデフォルト言語にフォールバック
- 翻訳ファイルはJSON形式で管理しやすく
